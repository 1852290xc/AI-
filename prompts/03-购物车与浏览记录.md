# Prompt 记录 03 · 购物车与浏览记录

> 真实开发记录，对应提交 `35dee1f`、`860040f`、`3e39450`、`06443af`、`90685a5`。

## 背景

参考淘宝购物车：一次结算多件、按加入时间倒序、失效商品置灰；
另外要一个按浏览时间倒序、可分天查看的浏览记录。

## 迭代 A：数据模型先定清楚

**给 AI 的指令**

```
两张表：
CartItem(user_id, product_id)  —— 唯一约束，一人一件只能加一次
SearchHistory(user_id, keyword, times) —— 同一关键词只留一条，重复搜索累加
浏览记录不新建表，复用 Behavior(action='view')，每次访问详情页写一条。

约束：
- 加购不能加自己的商品、不能加已售的；
- 结算只处理勾选的 ids，其余留在购物车；
- 结算时逐件建 Order 并把商品置 sold，跳过失效项并提示数量。
```

**AI 的第一版问题**：`checkout` 无条件结算整辆车，
和「可以支付一个或多个」的需求冲突。

**修复**：路由读 `request.form.getlist("ids")`，为空才结算全部；
前端每个商品一个 checkbox，底部实时算「已选合计」，按钮文案随数量变 `结算` / `结算(2)`。

## 迭代 B：浏览记录的顺序

**现象**：第一次实现按 `Behavior.id` 倒序，结果和「按浏览时间」不一致——
同一秒内多次浏览时，顺序会乱。

**给 AI 的指令**

```
排序改成 Behavior.created_at desc，id 只做次级排序；
按天分组：今天 / 昨天 / 更早；同一天内显示 HH:MM。
同一件商品多次浏览时标「重复浏览」，但每次都保留独立记录。
```

**结果**：提交 `860040f`。

## 迭代 C：测试为什么一次挂了三条

**现象**：`pytest` 跑到第 29 项失败，提示「不能把自己发布的商品加入购物车」。

**定位过程**（这一步比结果更有价值）：

```
打印 target.seller_id = 2，当前用户 id 也是 2
→ 说明登录的不是 lisi，而是上一条用例登录的 zhangsan
→ 因为 login() 里有 `if current_user.is_authenticated: redirect`
→ 测试里没先登出，lisi 的登录被直接忽略了
```

**修复**：测试里每次切换账号前先 `/auth/logout`；
把这个坑写进提交信息，避免以后再犯。

**结果**：33/33 通过，提交 `90685a5`。
