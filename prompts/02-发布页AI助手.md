# Prompt 记录 02 · 发布页 AI 助手（类型 / 型号 / 成色 / 估价）

> 真实开发记录，对应提交 `4b07424`、`5ba80de`、`46ff221`。

## 背景

发布页原本只有「分类 / 定价 / 文案」三个提示条，但用户仍然要自己想两件事：
这是什么型号？这件东西现在值多少钱？

## 迭代 A：先识别，再估价

**需求原话**

> 帮我插入通过 AI 鉴别商品类型、商品的状态（几成新）、商品的型号、分类、
> 来估算它的价值并向用户提供建议（仅提供建议，不强制）

**给 AI 的指令**

```
新增 listing_ai.py，提供 analyze_listing(title, description, original_price, comparables)：
1. 类型：复用 ai_engine.classify_product；
2. 型号：正则抽 iPhone 13 / 128G / 87键 / 42码，最多 3 个；
3. 成色：按词表判断（全新/九成新/…/有瑕疵），并返回命中的词；
4. 估价：优先用同型号可比价（≥3 条取中位数），否则原价×成色折扣，最后品类基价兜底；
5. 建议：3–4 条，最后一条必须写「以上都只是建议，最终价格由你决定」。
不要自动改用户的表单，全部由用户点「采用」才生效。
```

**AI 的第一版问题（重要）**

估价直接用「同品类中位价」，结果：

```
输入：九成新 iPhone 13 128G，原价 5999
输出：估价 ¥416–549（建议 ¥490）
```

原因：数码品类里 33 件商品，绝大多数是鼠标、键盘、充电宝，
中位数被拖到 400 多，iPhone 反而被低估了 8 倍。

**我怎么引导修复**

```
估价不能用「同品类」，要用「同型号」。
comparables 里带上标题，先按抽出来的型号 token 过滤（iphone / 13 / 128g），
过滤后不足 3 条才退回原价折算。
给个断言：iPhone 13 原价 5999、九成新，估价必须落在 2500–4500。
```

**修复后**：`¥3078–4056（建议 ¥3621）`，来源标注「参考了 4 件同型号商品的成交/在售价」。

## 迭代 B：面板不能和表单打架

**现象**：AI 判断成色是「九成新」，但下面的下拉框还停在默认的「全新」，
文案建议也按「全新」生成，页面自相矛盾。

**给 AI 的指令**

```
成色下拉框跟随 AI 判断，但只在这个用户还没手动改过的时候跟随。
用一个 condTouched 标记：用户 change 过就锁定，不再覆盖。
跟随的时候要 dispatch change，让定价和文案一起刷新。
```

**结果**：提交 `5ba80de`，页面四处信息（面板、下拉、定价、文案）一致。

## 可复现的验证

```bash
python test_smoke.py          # 34–36 项：型号/成色识别、估价区间、面板存在
curl -X POST localhost:5000/ai/analyze -H 'Content-Type: application/json' \
  -d '{"title":"九成新 iPhone 13 128G","original_price":5999}'
```

## 遗留

- 型号词典只覆盖数码与少量品类，服饰尺码、书籍版次还比较粗
- 估价没有区分「已成交」和「在售」价格，后续可以加权
